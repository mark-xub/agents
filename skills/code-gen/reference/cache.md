# `.code-gen/context.md` 缓存详规

主 SKILL.md 只保留"读→用→写"的骨架；此文件定义**内容清单**与**更新策略**。

## 该记（低频变、跨任务复用）

- **项目结构骨架**：顶层目录及各自职责。
- **命名与目录约定**：文件命名风格、模块目录层级、测试文件放置规则。
- **错误处理约定**：使用的异常类型、包装方式、日志格式、错误码规范。
- **技术栈与命令**：日志库、测试框架、构建/lint/测试/类型检查命令。
- **关键既有工具索引**：公共工具函数 / 类型 / interface / DTO 的所在目录路径。
- **已知的坑**：如"这个模块并发不安全"、"这个字段可能为 null"、"这里的 API 有配额限制"。
- **反向依赖热点**：被大量调用的核心符号（做 blast radius 分析的起点）。
- **文件头 frontmatter**：`generated_at` 时间戳，用于判断是否过时。

## 不该记（每次任务不同、一次性 artifact）

- 本次任务的 Plan
- 本次改动了哪些文件
- Reflection 内容 / 迭代记录
- 验证报告

## 更新策略

- **只增不删**：发现新工具、新约定、新坑 → append；旧条目**已明确失效**才修正。
- **禁止同一次任务里频繁重写整块**：缓存的价值来自跨任务积累，不是当次整理。
- **首次运行**：Phase 5（Execute 收尾）时按上述清单生成完整初版。
- **后续运行**：仅 append 增量条目 + 更新 `generated_at` 时间戳。
- **明确过时**：结构大变或用户显式要求"刷新 context"时才做全量重扫。

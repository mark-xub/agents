# Verify 详规（分层验证 + 迭代 Reflection）

主 SKILL.md 只保留"必须真跑、跑挂了迭代自修、三态透明"的骨架；此文件定义**层级定义**、**Reflexion 循环细节**和**反模式**。

## 分层验证

按从轻到重，每层都尝试执行；具体命令沿用 `.code-gen/context.md` 中记录的既有约定。

- **L0 静态检查 / 类型检查**：`tsc --noEmit`、`mypy`、`javac -Xlint`、`go vet` 等。语法/类型问题必须在这一层拦截。
- **L1 Lint / 格式**：`eslint`、`ruff`、`checkstyle`、`golangci-lint` 等。风格与低级坏味道。
- **L2 单元测试**：与本次改动直接相关的用例；若无既有测试且改动非平凡，本次新增最小覆盖。
- **L3 集成 / 端到端**：需要外部依赖（DB / 消息队列 / 第三方 API）的场景。多数临时环境不具备，允许 ⚠️。

## 三态透明报告

放在交付最后，禁止隐瞒：

- **✅ 已运行且通过** — 附命令 + 关键输出摘要。
- **⚠️ 环境不具备** — 说明缺什么（如"本地无 Redis"），并给出用户可自跑的命令。
- **⏭️ 本次不适用** — 说明为何不适用（如"纯文档改动"）。

推荐输出格式：

```markdown
## 验证报告

| 层级 | 状态 | 命令 / 说明 |
|------|------|-------------|
| L0 类型检查 | ✅ | `pnpm typecheck` — 无错误 |
| L1 Lint | ✅ | `pnpm lint` — 无警告 |
| L2 单元测试 | ⚠️ | 缺 `jest` 全局；用户可自跑 `pnpm test` |
| L3 集成 | ⏭️ | 本次仅改工具函数，不涉及集成路径 |

Reflection 迭代记录：
- 第 1 轮：类型报错 `T | undefined not assignable`，加空值分支修复。
- 第 2 轮：单测挂在边界 case，补 off-by-one 保护后通过。
```

## 迭代 Reflection（Reflexion 循环）

**先静态自审再真跑**，跑挂了用真实报错做下一轮输入，最多默认 3 轮：

1. **静态自审 `<reflection>`**，重点检查：
   - 空值处理：null / undefined / nil / Python `None` / Java `Optional.empty()` / 缺失的 key
   - 并发问题：async 竞态、线程安全、锁争用、非原子读写 — 按目标技术栈实际选择
   - 集合边界：越界访问、off-by-one、空集合的极端 case
   - 任何被忽略的边缘 case 或逻辑缺口
2. **执行分层验证中可跑的层级**，把真实报错原文（stack / diff / assertion）作为下一轮输入。
3. **失败 → 自修**：定位根因（不是绕过报错），给出最小改动；回到步骤 2。
4. **上限保护**：默认最多 3 次迭代；仍未通过则**停止自修**，向用户如实汇报：走过的路径、当前失败原因、需要用户决策的分歧点。

## 禁止的反模式

- 删除或跳过失败测试来"绿"
- 放宽断言以隐藏差异
- `try/except: pass`、`catch (e) {}` 等吞异常
- 用 mock 替换真实断言使其恒真
- 把 L3 环境缺失伪装成"已通过"
